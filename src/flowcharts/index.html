Robotic arm / Software overview

From slider to servo

Three high-level views of the Mac controller, Bluetooth link, and Pico firmware.

01

Mac application

Find the arm, take control, and turn user input into target packets.

While connected: poll ownership every 0.5 s and display status/errors. Bluetooth backpressure delays sending; newer slider values replace older pending values. After a disconnect, scanning resumes.

Code: ContentView.swift · BLEManager.swift

02

Bluetooth: Mac ↔ Pico

BLE = Bluetooth Low Energy. The Mac is the central; the Pico is the peripheral.

Owner releases or disconnects → Pico clears ownership and queues the safe pose (all logical joint targets = 0°). There is no inactivity timeout. The return path reports ownership, not measured arm position.

Code: BLEManager.swift · arm_ble_interface.c · arm_control_service.gatt

03

Pico firmware & control loop

Core 1 handles BLE; Core 0 applies events and sends servo commands.

XYZ mode: inverse kinematics (IK) calculates positioning joints 3–6; joints 1–2 stay manual. If IK fails, hold the last valid pose. This loop sends position commands without measured-position feedback; servo-bus initialization failure leaves outputs idle.

Code: main.c · arm_kinematics.c · servo_bus.cpp
